# 短视频反诈后端 — API 技术文档

> **适用版本**: v2.0 | **更新日期**: 2026-06-09 | **Base URL**: `http://<host>:8080`

---

## 1. 通用约定

### 1.1 统一响应格式

所有接口返回 `ApiResponse<T>`，`@JsonInclude(NON_NULL)` 下 null 字段不序列化：

```json
{
  "code": 200,
  "message": "success",
  "data": { ... }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | `200` 成功，其他值表示错误 |
| `message` | String | 错误时为可读描述，成功时固定 `"success"` |
| `data` | T / null | 响应体；为 null 时字段从 JSON 中消失 |

### 1.2 认证

所有 `/api/**` 业务接口需在 Header 中携带 API Key。`/actuator/**` 免认证。

```
X-API-Key: <your-api-key>
```

- Root Key（`${API_KEY}` 配置值）拥有全部权限且不限流
- 动态 Key 通过 `/api/v1/keys/register` 注册获得，默认权限 `DETECT,HISTORY`，默认限流 20 req/60s
- 缺失/无效 Key → **401** `{"code":401,"message":"Missing or invalid API key"}`

### 1.3 限流

动态 Key 默认 **20 req/60s**，每个响应携带以下 Header：

| Header | 含义 |
|--------|------|
| `X-RateLimit-Limit` | 窗口上限 |
| `X-RateLimit-Remaining` | 本窗口剩余 |
| `X-RateLimit-Reset` | 窗口重置时间 (epoch 秒) |

超限返回 **429**，同时携带 `Retry-After` 头（秒数）：

```json
{"code":429,"message":"请求过于频繁，请稍后再试"}
```

### 1.4 HTTP 状态码汇总

| HTTP status | 场景 |
|-------------|------|
| 200 | 成功 |
| 202 | 异步任务已提交（仅 `POST /detect/async`） |
| 400 | 参数缺失 / 校验失败 / 文件超限 / 格式不符 |
| 401 | 未认证（缺少或无效 API Key） |
| 404 | 资源不存在（任务 ID / Key ID 无效） |
| 429 | 请求过于频繁（限流触发） |
| 500 | 服务器内部错误 |
| 502 | AI 分析服务不可用（含重试耗尽） |
| 503 | 数据库/缓存访问异常 |

## 3. 检测接口

### 3.1 POST /api/v1/detect — 同步检测

上传视频进行反欺诈分析，同步返回结果。

**Content-Type:** `multipart/form-data`

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `deviceId` | String | **是** | 设备唯一标识 |
| `authorId` | String | **是** | 发布者 ID（用于黑名单检查） |
| `video` | File | **是** | 视频文件，仅支持 MP4 格式，≤10MB |

**视频校验规则（VideoValidator）：**
1. 文件不能为空
2. Content-Type 必须为 `video/mp4`
3. 文件名后缀必须为 `.mp4`
4. 文件头 4-7 字节必须为 `ftyp`（MP4 魔数校验），否则报"视频文件已损坏或格式不正确"

**响应 data (DetectResponse)：**

| 字段 | 类型 | 出现条件 | 说明 |
|------|------|----------|------|
| `riskLevel` | String | 始终 | `HIGH` / `MEDIUM` / `SAFE` |
| `reason` | String | 非 SAFE 时 | 判断依据；SAFE 时为 null 故不出现 |
| `score` | Double | 非黑名单命中时 | 风险分数 [0.0, 1.0] |
| `transcription` | String | 正常 AI 流程时 | AI 语音转文本结果 |
| `source` | String | 仅黑名单命中时 | `authority` / `global` / `temp` |

**三种结果路径：**

```
路径 1 — 黑名单命中（不调 AI，不写库，不计入 stats 正常检测量）
  检测优先级: authority > global > temp（命中即返回）
  响应: {"riskLevel":"HIGH","reason":"权威黑名单发布者","source":"authority"}
  特征: 无 score、transcription 字段

路径 2 — 关键词命中（调用 AI，aiResult.keywordHit=true）
  响应: {"riskLevel":"HIGH","reason":"关键词命中","score":1.0,"transcription":"转账汇款..."}

路径 3 — 综合评分（调用 AI，aiResult.keywordHit=false）
  score = 0.7 × aiGlitchProb + 0.3 × violenceProb
  score ≥ 0.6 → HIGH, reason="综合评分过高"
  score ∈ [0.3, 0.6) → MEDIUM, reason="综合评分中等"
  score < 0.3 → SAFE, reason=null（不出现）
  响应: {"riskLevel":"HIGH|MEDIUM|SAFE","score":0.43,"reason":"...","transcription":"..."}
```

**后续行为：**
- 结果 HIGH → 自动将 authorId 加入临时黑名单（TTL 24h）
- 所有结果（除黑名单命中）均写入 MySQL `t_detection_record`，`raw_ai_result` 字段存 AI 原始响应 JSON

**示例请求：**
```kotlin
val body = MultipartBody.Builder()
    .setType(MultipartBody.FORM)
    .addFormDataPart("deviceId", deviceId)
    .addFormDataPart("authorId", authorId)
    .addFormDataPart("video", "video.mp4", videoBytes.toRequestBody("video/mp4".toMediaType()))
    .build()
```

**示例响应（综合评分-HIGH）：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "riskLevel": "HIGH",
    "reason": "综合评分过高",
    "score": 0.655,
    "transcription": "转账汇款..."
  }
}
```

**示例响应（黑名单命中）：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "riskLevel": "HIGH",
    "reason": "权威黑名单发布者",
    "source": "authority"
  }
}
```

**示例响应（SAFE）：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "riskLevel": "SAFE",
    "score": 0.12,
    "transcription": "今天天气真不错..."
  }
}
```

**响应示例：**
```json

  "code": 202,
  "message": "任务已提交",
  "data": {
    "taskId": "a1b2c3d4e5f6",
```

## 4. 历史查询接口

### GET /api/v1/history

查询检测历史记录，支持过滤条件 + 两种分页模式。

**请求参数：**

| 参数 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| `deviceId` | String | **是** | — | 设备标识 |
| `afterId` | Long | 否 | — | 游标：返回此 ID 之后的记录（增量同步模式） |
| `page` | int | 否 | 1 | 页码（afterId 存在时忽略），最小 1 |
| `size` | int | 否 | 20 | 每页条数，范围 [1, 100]，超出自动修正为 20 |
| `authorId` | String | 否 | — | 按发布者 ID 过滤 |
| `riskLevel` | String | 否 | — | 按风险等级过滤: `HIGH` / `MEDIUM` / `SAFE` |
| `startDate` | String | 否 | — | 起始日期（ISO DATE，如 `2026-06-01`） |
| `endDate` | String | 否 | — | 截止日期（ISO DATE，如 `2026-06-09`） |

**模式对比：**

| 模式 | 参数 | 适用场景 |
|------|------|----------|
| 增量同步 | `afterId` 不为 null | APP 启动时拉取新记录，`page` 被忽略 |
| 分页浏览 | `afterId` 为 null | 首次加载 / 上拉加载更多 |

**响应 data (HistoryResponse)：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `records` | HistoryItem[] | 记录列表（不含 raw_ai_result） |
| `total` | long | 符合条件的总记录数 |
| `page` | int | 当前页码 |
| `size` | int | 当前页大小 |
| `hasMore` | boolean | 是否有更多数据 |
| `latestId` | Long | 当前批次最大 ID（用于下次 afterId） |

**records 元素 (HistoryItem)：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | Long | 记录 ID（全局递增） |
| `deviceId` | String | 设备 ID |
| `authorId` | String | 发布者 ID |
| `riskLevel` | String | `HIGH` / `MEDIUM` / `SAFE` |
| `score` | Double | 风险评分 |
| `createdAt` | String | 检测时间（ISO 8601） |

**示例请求：**

```
GET /api/v1/history?deviceId=X&authorId=user123&riskLevel=HIGH&startDate=2026-06-01&endDate=2026-06-09&page=1&size=20
```

**示例响应：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [
      {
        "id": 142,
        "deviceId": "device-abc",
        "authorId": "user123",
        "riskLevel": "HIGH",
        "score": 0.85,
        "createdAt": "2026-06-09T14:30:00"
      }
    ],
    "total": 5,
    "page": 1,
    "size": 20,
    "hasMore": false,
    "latestId": 142
  }
}
```

## 5. 黑名单接口

三层黑名单：`authority`（权威永久）> `global`（管理永久）> `temp`（自动/手动，24h TTL）

### 5.1 GET /api/v1/blacklist/check/{authorId} — 综合查询

一次查询三层，按优先级返回最先命中结果。

**路径参数：**

| 参数 | 类型 | 说明 |
|------|------|------|
| `authorId` | String | 发布者 ID |

**响应 data (BlacklistHit)：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `hit` | boolean | 是否命中任一黑名单 |
| `source` | String | `authority` / `global` / `temp`（命中时） |
| `reason` | String | 命中原因（命中时） |

**响应示例：**
```json
// 命中
{"code":200,"message":"success","data":{"hit":true,"source":"authority","reason":"权威黑名单发布者"}}

// 未命中
{"code":200,"message":"success","data":{"hit":false,"source":null,"reason":null}}
```

### 5.2 各层 CRUD 接口

三层黑名单接口结构完全一致，仅路径前缀不同。以下以 authority 为例：

| 方法 | 路径 | Request Body | 说明 |
|------|------|-------------|------|
| GET | `/authority` | — | 列出所有成员 |
| GET | `/authority/{authorId}` | — | 检查是否在名单中 → `{"blacklisted": true/false}` |
| POST | `/authority` | `{"authorId": "xxx"}` | 添加成员 |
| DELETE | `/authority/{authorId}` | — | 移除成员 |

**Temp 层差异：**
- `POST /temp` 额外支持可选 `reason` 字段：`{"authorId": "xxx", "reason": "原因"}`，默认 `"手动添加"`
- `GET /temp/{authorId}` 返回额外 `ttlSeconds` 字段：`{"blacklisted": true, "ttlSeconds": 86352}`
- Temp 24 小时后自动过期
- HIGH 风险检测后系统自动加入 temp，reason 为风险评估结果

## 6. API Key 管理接口

### 6.1 POST /api/v1/keys/register — 设备注册

APP 首次启动时调用，同一 deviceId 重复注册返回已有 Key（幂等）。

**Request Body (JSON)：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `deviceId` | String | **是** | 设备唯一标识 |
| `deviceName` | String | 否 | 设备昵称，默认取 deviceId |

**响应 data (KeyRegisterResponse)：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `apiKey` | String | 生成的 API Key（32 位 hex） |
| `expiresAt` | String | 过期时间（ISO 8601），null 表示永不过期 |

**注意：** 注册接口无需认证（`ROLE_DETECT` 即可访问实际业务接口；注册时 Key 还未获得）。

### 6.2 管理接口（需 ADMIN 角色）

| 方法 | 路径 | Request Body | 说明 |
|------|------|-------------|------|
| GET | `/api/v1/keys` | — | 列出所有 Key（不含 keyValue 字段） |
| GET | `/api/v1/keys/{id}` | — | 查看单个 Key 详情（含 keyValue） |
| POST | `/api/v1/keys` | 见下 | 管理员创建 Key |
| PUT | `/api/v1/keys/{id}` | 见下 | 更新 Key 属性 |
| POST | `/api/v1/keys/{id}/revoke` | — | 撤销 Key（可逆，status 变为 REVOKED） |
| DELETE | `/api/v1/keys/{id}` | — | 删除 Key（不可逆，物理删除） |

**POST /api/v1/keys body：**
```json
{
  "keyName": "测试设备",
  "permissions": "DETECT,HISTORY",
  "rateLimit": 30,
  "expiredAt": "2026-12-31T23:59:59"
}
```
- `keyName` 默认 `"手动创建"`，`permissions` 默认 `"DETECT,HISTORY"`
- `rateLimit` 默认 20，`expiredAt` 不传则永不过期

**PUT /api/v1/keys/{id} body：** 同上，各字段均可选，只有传的字段才更新。

**KeyInfo 字段：**

| 字段 | 列表 | 详情 | 说明 |
|------|------|------|------|
| `id` | ✓ | ✓ | Key ID |
| `keyValue` | ✗ | ✓ | 密钥值（列表出于安全不返回） |
| `keyName` | ✓ | ✓ | 名称/备注 |
| `deviceId` | ✓ | ✓ | 关联的设备 ID |
| `permissions` | ✓ | ✓ | 权限，逗号分隔 |
| `status` | ✓ | ✓ | ACTIVE / REVOKED |
| `rateLimit` | ✓ | ✓ | 限流次数/窗口 |
| `lastUsedAt` | ✓ | ✓ | 最后使用时间 |
| `expiredAt` | ✓ | ✓ | 过期时间 |
| `createdAt` | ✓ | ✓ | 创建时间 |
| `revokedAt` | ✗ | ✓ | 撤销时间（仅详情） |

## 8. 健康检查

### GET /actuator/health

免认证。返回服务及依赖组件健康状态。

```json
{
  "status": "UP",
  "components": {
    "db": {"status": "UP"},
    "redis": {"status": "UP"},
    "aiService": {"status": "UP"}
  }
}
```

`aiService` 仅检查 AI 服务是否可达（任何 HTTP 响应均视为 UP，仅连接级失败才返回 DOWN）。

## 9. 枚举定义

### RiskLevel

| 值 | 含义 |
|----|------|
| `HIGH` | 高风险（黑名单/关键词命中/综合分 ≥ 0.6） |
| `MEDIUM` | 中风险（综合分 [0.3, 0.6)） |
| `SAFE` | 安全（综合分 < 0.3） |

### TaskStatus

| 值 | 含义 |
|----|------|
| `PENDING` | 待处理 |
| `PROCESSING` | 处理中 |
| `DONE` | 已完成 |
| `FAILED` | 失败 |

### 黑名单 source

| 值 | 含义 | TTL |
|----|------|-----|
| `authority` | 权威黑名单（官方平台发布） | 永久 |
| `global` | 全局黑名单（管理员添加） | 永久 |
| `temp` | 临时黑名单（系统自动/手动） | 24 小时 |

## 10. APP 接入流程

### 10.1 首次启动

```
1. 生成/读取本地 deviceId（UUID），持久化
2. POST /api/v1/keys/register  body: {"deviceId":"xxx","deviceName":"xxx"}
3. 持久化返回的 apiKey，后续所有请求携带 X-API-Key header
4. GET /api/v1/history?deviceId=X&size=50  拉取历史列表首页
5. 持久化 latestId 作为 lastSyncedId
```

### 10.2 视频检测

```
1. POST /api/v1/detect  (multipart: deviceId, authorId, video)
2. 解析响应:
   - riskLevel=HIGH → 阻止发布，展示 reason + source
   - riskLevel=MEDIUM → 警告，建议人工审核
   - riskLevel=SAFE → 放行
3. 本地缓存本次记录，更新 lastSyncedId
```

### 10.3 冷启动增量同步

```
1. GET /api/v1/history?deviceId=X&afterId=<本地lastSyncedId>&size=50
2. 新记录合并到本地列表头部
3. hasMore=true → 用 latestId 继续拉取直到 hasMore=false
4. 持久化 latestId
```

### 10.4 限流处理

```
收到 429 + Retry-After 头时:
- 等待 Retry-After 秒后重试
- 或切换到次低频率的调用策略
```

## 12. APP 接入指南

### 阻塞项（必须适配，否则功能不可用）

| # | 事项 | 类型 | 说明 | 不加会怎样 |
|---|------|------|------|-----------|
| 1 | X-API-Key Header 认证 | **强制接入** | 所有 /api/** 请求必须携带 `X-API-Key` header | **所有接口返回 401**，APP 完全无法使用 |
| 2 | 首次注册获取 Key | **强制接入** | APP 冷启动时调用 `POST /api/v1/keys/register`，持久化返回的 `apiKey` | 无有效 Key 可用，**所有接口返回 401** |
| 3 | 处理 429 限流 | **强制接入** | 动态 Key 默认 20 req/60s，超限返回 429 + `Retry-After` 头 | 用户快速操作时**请求被拒绝**，需等待 Retry-After 秒后重试 |
| 4 | SAFE 时 reason 字段不返回 | **兼容风险** | SAFE 结果下 `reason` 为 null，JSON 中该字段不出现 | 老 APP 如不判空直接读 `reason` 字段**可能崩溃（NPE）** |
| 5 | 黑名单命中时 score 不返回 | **兼容风险** | 黑名单命中时无 `score` 字段 | 老 APP 如强制读取 `score` **可能崩溃（NPE）** |

### 可选接入项（不接入不影响现有功能）

| # | 事项 | 类型 | 说明 |
|---|------|------|------|
| 6 | 异步检测接口 | 新增接口 | `POST /api/v1/detect/async` + `GET /api/v1/detect/{taskId}/status`，适合大视频或高并发场景 |
| 7 | 历史过滤参数 | 新增参数 | `authorId`、`riskLevel`、`startDate`、`endDate` 过滤，提升历史查询体验 |
| 8 | latestId 字段 | 新增字段 | `HistoryResponse.latestId`，可作为增量同步游标，替代手动管理 afterId |
| 9 | 限流响应头 | 新增 Header | `X-RateLimit-Limit`、`X-RateLimit-Remaining`、`X-RateLimit-Reset`，可展示剩余配额 |
| 10 | 视频 MP4 魔数校验 | 校验增强 | 上传非 MP4 格式会被 400 拒绝，需确保录制输出为合法 MP4 |
| 11 | 新增 HTTP 错误码 | 错误码 | 502（AI 不可用）、503（DB/Redis 异常），应给出友好提示而非通用"网络错误" |

### 错误码处理建议

| HTTP 状态码 | 含义 | APP 建议处理 |
|-------------|------|-------------|
| 200 | 成功 | 正常解析 data |
| 202 | 异步任务已提交 | 记录 taskId，开始轮询 |
| 400 | 参数错误 | 检查 deviceId/authorId/video 是否完整，video 格式是否合法 |
| 401 | 未认证 | 检查 X-API-Key header，若 Key 过期则重新注册 |
| 404 | 资源不存在 | 任务已过期（24h）或 Key ID 无效 |
| 429 | 限流 | 等待 `Retry-After` 秒后重试，或降低调用频率 |
| 500 | 服务器内部错误 | 一般性重试，提示"服务异常" |
| 502 | AI 服务不可用 | 提示"AI 分析繁忙，请稍后重试"，可自动重试 |
| 503 | 数据库/缓存异常 | 提示"服务暂时不可用"，稍后重试 |

### 关键字段判空规范

```
DetectResponse 解析必须遵循以下判空顺序：

1. 读取 riskLevel（始终存在）
2. 若 data.source != null → 黑名单命中流程，展示 reason + source
3. 若 data.source == null → 正常检测流程
   a. data.score 存在（SAFE/MEDIUM/HIGH 均有）
   b. data.reason 可能为 null（SAFE 时不返回），需判空
   c. data.transcription 正常流程始终存在
```
