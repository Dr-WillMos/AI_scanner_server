## 1. 项目概述

短视频反诈后端是一个基于 **Spring Boot** 的 RESTful 服务，核心功能是接收客户端上传的短视频，调用外部 Python AI 分析服务对视频内容进行风险评估，并维护一个高风险发布者黑名单。

### 核心能力

| 能力 | 说明 |
|------|------|
| 视频检测 | 接收 MP4 视频（≤5s），返回 HIGH / MEDIUM / SAFE 三级风险判定 |
| 黑名单管理 | Redis 驱动的黑名单 CRUD，命中后直接短路返回 HIGH，不调用 AI |
| 结果持久化 | 每次检测结果写入 MySQL，保留完整 AI 原始返回供审计 |
| 风险评分 | 加权公式：`0.7 × aiGlitchProb + 0.3 × violenceProb`，结合关键词命中判定 |

### 调用链路

```
Client → DetectionController.detect()
           │
           ├─ (1) BlacklistService.isBlacklisted(authorId) → Redis SET 查询
           │       └─ 命中 → 直接返回 HIGH，短路，不调用 AI
           │
           ├─ (2) AiClient.analyze(video) → HTTP POST multipart → Python AI
           │
           ├─ (3) RiskCalculator.calculate(glitch, violence, keywordHit)
           │       └─ 返回 Result(riskLevel, score, reason)
           │
           ├─ (4) DetectionRecordMapper.insert(record) → MySQL
           │
           └─ (5) 返回 DetectResponse → Client
```

## 5. 核心业务 — 检测流水线

`DetectionService.detect()` 是核心业务入口，完整流程如下：

### 流程图

```
输入: deviceId, authorId, MultipartFile(video)
          │
          ▼
┌─────────────────────┐
│ 1. 查询 Redis 黑名单  │
│    authorId ∈ Set?  │
└────────┬────────────┘
         │
    ┌────▼────┐
    │ 命中?    │
    └────┬────┘
    YES  │          NO
    ┌────▼──────────────────┐
    │ 返回 HIGH +           │
    │ reason="黑名单发布者"   │
    │ (不调 AI, 不写 DB)    │
    └──────────────────────┘
         │
         ▼
┌─────────────────────────┐
│ 2. 调用 AI 服务           │
│    POST /v1/analyze/video │
│    multipart/form-data   │
│    携带 MP4 文件          │
└────────┬────────────────┘
         │
         ▼
┌─────────────────────────┐
│ 3. 解析 AI 返回           │
│    - aiGlitchProb        │
│    - violenceProb        │
│    - transcription       │
│    - keywordHit          │
└────────┬────────────────┘
         │
         ▼
┌─────────────────────────────┐
│ 4. 风险评分 (RiskCalculator) │
│                              │
│  keywordHit == true?         │
│    ├─ YES → HIGH (1.0)       │
│    └─ NO:                    │
│       score = 0.7×glitch     │
│              + 0.3×violence  │
│       ├─ ≥0.6 → HIGH         │
│       ├─ ≥0.3 → MEDIUM       │
│       └─ <0.3 → SAFE         │
└────────┬────────────────────┘
         │
         ▼
┌─────────────────────────┐
│ 5. 持久化到 MySQL         │
│    INSERT INTO           │
│    t_detection_record    │
└────────┬────────────────┘
         │
         ▼
┌─────────────────────────┐
│ 6. 返回 DetectResponse   │
│    - riskLevel           │
│    - score               │
│    - reason              │
│    - transcription       │
└─────────────────────────┘
```

### 关键设计点

1. **黑名单短路**: 命中黑名单时不调用 AI 也不写数据库，最大限度减少无效开销
2. **AI 调用失败传播**: AiClient 将异常包装为 `RuntimeException`，由 `GlobalExceptionHandler` 统一返回 500
3. **原始 AI 结果全量保存**: `raw_ai_result` 字段以 JSON 字符串存储 AI 的完整返回，便于事后审计和模型调优
4. **关键词优先**: `keywordHit` 为 true 时直接判 HIGH，不与概率加权，体现"敏感词零容忍"策略

## 7. 风险评分算法

`RiskCalculator` 是一个 **纯函数组件** (`@Component`)，无副作用，便于单元测试。

### 判定逻辑

```
输入: aiGlitchProb (0.0 ~ 1.0), violenceProb (0.0 ~ 1.0), keywordHit (boolean)

if keywordHit == true:
    → HIGH (score = 1.0, reason = "关键词命中")

score = 0.7 × aiGlitchProb + 0.3 × violenceProb

if score >= 0.6:    → HIGH   (reason = "综合评分过高")
if score >= 0.3:    → MEDIUM (reason = "综合评分中等")
if score < 0.3:     → SAFE   (reason = null)
```

### 权重说明

- **aiGlitchProb（AI 合成痕迹概率）**: 权重 0.7，主要判别维度。AI 换脸/合成类诈骗视频在这一维度得分高
- **violenceProb（暴力内容概率）**: 权重 0.3，辅助维度

### 边界值测试

| aiGlitchProb | violenceProb | score | 结果 |
|-------------|-------------|-------|------|
| 0.60 | 0.60 | 0.60 | **HIGH** (≥0.6) |
| 0.30 | 0.30 | 0.30 | **MEDIUM** (≥0.3) |
| 0.29 | 0.29 | 0.29 | **SAFE** (<0.3) |
| 0.85 | 0.20 | 0.655 | **HIGH** |
| 0.50 | 0.20 | 0.41 | **MEDIUM** |
| 0.10 | 0.10 | 0.10 | **SAFE** |

## 8. 数据库设计

### 8.1 数据库信息

- **数据库名**: `aiscanner`
- **字符集**: `utf8mb4` / `utf8mb4_unicode_ci`
- **引擎**: InnoDB

### 8.2 检测记录表 `t_detection_record`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| device_id | VARCHAR(128) | NOT NULL | 设备 ID |
| author_id | VARCHAR(128) | NOT NULL | 抖音作者号 |
| risk_level | VARCHAR(16) | NOT NULL | 风险等级: HIGH / MEDIUM / SAFE |
| score | DOUBLE | NOT NULL, DEFAULT 0.0 | 风险加权分数 |
| raw_ai_result | TEXT | NULLABLE | AI 服务原始返回 JSON |
| created_at | DATETIME | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 创建时间 |

### 8.3 索引

| 索引名 | 字段 | 用途 |
|--------|------|------|
| PRIMARY | id | 主键 |
| idx_device_id | device_id | 按设备查询历史检测记录 |
| idx_author_id | author_id | 按作者查询历史检测记录 |
| idx_risk_level | risk_level | 按风险等级筛选统计 |
| idx_created_at | created_at | 时间范围查询 |

### 8.4 DDL

完整建表语句见 `src/main/resources/sql/init.sql`。

```sql
CREATE TABLE IF NOT EXISTS t_detection_record (
    id              BIGINT       NOT NULL AUTO_INCREMENT  COMMENT '主键',
    device_id       VARCHAR(128) NOT NULL                 COMMENT '设备ID',
    author_id       VARCHAR(128) NOT NULL                 COMMENT '抖音作者号',
    risk_level      VARCHAR(16)  NOT NULL                 COMMENT '风险等级',
    score           DOUBLE       NOT NULL DEFAULT 0.0     COMMENT '风险加权分数',
    raw_ai_result   TEXT                                  COMMENT 'AI 服务原始返回 JSON',
    created_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (id),
    INDEX idx_device_id (device_id),
    INDEX idx_author_id (author_id),
    INDEX idx_risk_level (risk_level),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

## 9. 缓存设计（Redis）

### 9.1 黑名单存储

| 项目 | 值 |
|------|-----|
| 数据结构 | **Set** |
| Key | `blacklist:authors` |
| 存储内容 | authorId 字符串集合 |
| 持久化 | 依赖 Redis 自身 RDB/AOF 策略（应用层无额外持久化） |

### 9.2 操作命令映射

| 业务操作 | Redis 命令 |
|----------|-----------|
| `isBlacklisted(id)` | `SISMEMBER blacklist:authors {id}` |
| `add(id)` | `SADD blacklist:authors {id}` |
| `remove(id)` | `SREM blacklist:authors {id}` |
| `listAll()` | `SMEMBERS blacklist:authors` |
| `size()` | `SCARD blacklist:authors` |

### 9.3 序列化配置

- **Key 序列化**: `StringRedisSerializer`
- **Value 序列化** (通用 RedisTemplate): `Jackson2JsonRedisSerializer`
- **StringRedisTemplate**: 用于黑名单操作，直接操作字符串

### 9.4 连接池（Lettuce）

| 参数 | 值 |
|------|-----|
| max-active | 8 |
| max-idle | 8 |
| min-idle | 2 |
| max-wait | 3000ms |
| connect-timeout | 5000ms |
| timeout | 3000ms |

## 11. 异常处理

`GlobalExceptionHandler` 使用 `@RestControllerAdvice` 统一拦截异常，返回 `ApiResponse` 格式。

| 异常类型 | HTTP 状态码 | 返回 message |
|----------|-------------|-------------|
| `MaxUploadSizeExceededException` | 400 | 视频文件过大，最大支持 10MB |
| `MissingServletRequestParameterException` | 400 | 缺少必要参数: {paramName} |
| `MultipartException` | 400 | 请求必须包含视频文件 |
| `IllegalArgumentException` | 400 | 异常消息原文 |
| `Exception` (兜底) | 500 | 服务器内部错误 |

**设计原则**：对外不暴露内部异常堆栈，仅返回用户可读的错误描述。详细错误信息输出到服务端日志（`log.error`）。
